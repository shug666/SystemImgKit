## MODIFIED Requirements

### Requirement: Updated flash.sh script
The generated `flash.sh` SHALL assume the device is already in fastboot mode (it SHALL NOT issue `adb reboot fastboot`). It SHALL include: a wait-for-fastboot-device check (`fastboot getvar product` with a fallback `sleep`), `fastboot erase system`, `fastboot flash system`, `fastboot --disable-verification flash vbmeta` (if vbmeta.img is available next to the source image), commented resize-logical-partition commands for dynamic partitions, and `fastboot -w` + `fastboot reboot`. The script SHALL NOT invoke `adb` anywhere. The header prerequisites SHALL name only `fastboot` (not `adb`) and SHALL state the device must already be in fastboot mode.

#### Scenario: vbmeta auto-detected
- **WHEN** a vbmeta.img exists next to the source image
- **THEN** the flash.sh script references it and disables verification

#### Scenario: No adb reboot issued
- **WHEN** a `flash.sh` is generated by `pack`
- **THEN** the script does not contain the string `adb reboot fastboot` and does not invoke `adb`

#### Scenario: Device expected to be in fastboot already
- **WHEN** the user inspects the generated `flash.sh` header
- **THEN** the prerequisites state the device must already be in fastboot mode and do not mention `adb`
